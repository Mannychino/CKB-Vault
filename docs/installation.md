## CKB Vault — Local Development Setup
This guide explains how to install, configure, build, test, deploy, and run the **CKB Vault** project on a local development machine.
The project is designed to run against a local **Nervos CKB devnet** using **OffCKB**. The Rust smart contract is tested with **CKB Testtool**, while deployment and transaction interaction are performed against the local CKB node.

> **Important:** This project is intended for local development and testing. The development accounts generated by OffCKB are test accounts and must never be used with real funds.

# Project Requirements
1. Git
2. node JS
3. Typescript
4. Rust compiler
5. Offckb
6. CKB Debugger

# Recommended Environment
The recommended development environment is:
Linux (preferably)
Using WSL2 is recommended when developing on Windows because the CKB/Rust development toolchain is more naturally suited to a Linux environment.
Linux users can run the project directly without WSL.
The Vault contract is compiled for:
```
riscv64imac-unknown-none-elf
```
Install the target:
```bash
rustup target add riscv64imac-unknown-none-elf
```
Verify:
```
rustup target list --installed
```
You should see:

```text
riscv64imac-unknown-none-elf
```


## Quick Workflow

## Clone the Project

Clone the repository:

```bash
git clone (https://github.com/Mannychino/CKB-Vault.git)
```


Setup the OFFCKB NODE
```
  offckb node

```
### In the second terminal, list the pre-funded Devnet accounts:
```
offckb accounts

```

## Build the Rust contract 

```
cd contracts/vault-lock

cargo build \
  --release \
  --target riscv64imac-unknown-none-elf \
  --features contract \
  --bin vault-lock
``` 
Once your build the contract you can verify using 

ls -lh \
target/riscv64imac-unknown-none-elf/release/vault-lock 

and 
 
 file \
target/riscv64imac-unknown-none-elf/release/vault-lock

```
contracts/vault-lock/target/riscv64imac-unknown-none-elf/release/vault-lock
```
## Check the Compiled Contract
Before deploying, calculate the Blake2b hash of the compiled binary.
From the project root:

```bash
ckb-cli util blake2b \
  --binary-path contracts/vault-lock/target/riscv64imac-unknown-none-elf/release/vault-lock
```
## Deploy the Script
```
cd ~/CKB-Vault


offckb deploy \
  --network devnet \
  --target contracts/vault-lock/target/riscv64imac-unknown-none-elf/release/vault-lock \
  --output contracts/vault-lock/deployment
``` 
Check the scripts.json and system-scripts.json

## Export the System Script
```
offckb system-scripts \
  --output contracts/vault-lock/deployment/system-scripts.json

  ```

## Compile the Typescript file
``` 
  pnpm exec tsc
```
**You should not expect any output**

## Choose A funded Account to fund the vault
```
offckb accounts
```
**For Local Development You can use the private key.**
```
offckb accounts --show-private-keys
```

## Configure account
```
  export CKB_PRIVATE_KEY="private key"
export CKB_RPC_URL="Your CKB RPC URL"
export CKB_RPC_FALLBACK="YOUR_CKB_RPC_URL"

```
**Optionally you can export vault amount and vault Timelock**
```
export VAULT_AMOUNT="5000"
export VAULT_TIMELOCK="100"
```
## Create vault
```
  node dist-ts/contracts/vault-lock/scripts/create_vault.js
```

***Copy the generated Vault Cell transaction hash and export***
```
export VAULT_TX_HASH="0xYOUR_VAULT_TX_HASH"
export VAULT_INDEX="0"

```
### Withdraw
```
  node dist-ts/contracts/vault-lock/scripts/withdraw_vault.js
```

If the devnet is reset or the vault contract is redeployed, regenerate or recheck `scripts.json` and `system-scripts.json` before creating another vault.

### Start the frontend server
```
node frontend-v1/server.mjs

```

## Security Warning

The private keys generated by OffCKB are development keys.

They are intentionally available for local testing.

Never use them with:
* CKB mainnet
* Real funds
* Production applications
* Production wallets
Likewise, never commit private keys to GitHub.
For local testing, private keys should be supplied through a secure local environment variable or the development tooling provided by OffCKB.
