# Installation Guide

## CKB Vault — Local Development Setup
This guide explains how to install, configure, build, test, deploy, and run the **CKB Vault** project on a local development machine.
The project is designed to run against a local **Nervos CKB devnet** using **OffCKB**. The Rust smart contract is tested with **CKB Testtool**, while deployment and transaction interaction are performed against the local CKB node.

> **Important:** This project is intended for local development and testing. The development accounts generated by OffCKB are test accounts and must never be used with real funds.

# 13. TypeScript Configuration

The root `tsconfig.json` is used to compile the TypeScript scripts.

The important configuration is:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": ".",
    "outDir": "dist-ts",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "types": ["node"]
  },
  "include": [
    "contracts/**/*.ts"
  ]
}
```

The `rootDir` is important because the project contains TypeScript files underneath:

```text
contracts/
```

Without the correct `rootDir`, newer TypeScript versions can produce an error similar to:

```text
TS5011:
The common source directory ... must be explicitly set
```

# 17. Check the Compiled Contract

Before deploying, calculate the Blake2b hash of the compiled binary.

From the project root:

```bash
ckb-cli util blake2b \
  --binary-path contracts/vault-lock/target/riscv64imac-unknown-none-elf/release/vault-lock
```

This produces the contract's Blake2b hash.

The hash is important because CKB identifies scripts using their:

```text
code_hash
+
hash_type
+
args
```

For this project, the deployed Vault contract uses:

```text
hashType: data2
```

# 22. Deploy the Vault Contract

After building the Rust contract and starting the CKB devnet, deploy the contract with OffCKB.

From the project root:

```bash
offckb deploy \
  --network devnet \
  --target ./contracts/vault-lock/target/riscv64imac-unknown-none-elf/release/vault-lock \
  --output ./contracts/vault-lock/deployment
```

OffCKB will ask for confirmation.

Confirm the deployment.

A successful deployment produces a transaction hash similar to:

```text
contract vault-lock deployed, tx hash:
0xb596420ac646a86316d6133df789d3f8fe3495970265587f266f380492e59484
```

The exact transaction hash will be different for a new deployment.

```text

```

These values are required by the TypeScript application when constructing transactions that use the Vault lock script.

---

# 24. Understanding the Cell Dependency

The deployed Vault contract has a deployment Cell.

The frontend/application does not simply reference the contract by name.

It needs to reference the actual deployed code through a **Cell Dependency**.

Conceptually:

```text
Vault Contract
      ↓
Deployment Cell
      ↓
Transaction CellDep
      ↓
CKB executes vault-lock
```

For example, the deployment record may contain:

```text
codeHash:
0x...

hashType:
data2

txHash:
0x...

index:
0
```

The exact values depend on the deployment.

---

# 25. Important: Deployment Changes the Cell Dependency

Every time the contract is redeployed, the deployment transaction can change.

Therefore, the following information may also change:

```text
deployment txHash
cellDep
deployment artifacts
```

If the frontend uses an old `scripts.json` after deploying a new contract, transactions can fail with an error such as:

```text
TransactionFailedToResolve

Unknown OutPoint
```

This usually means the transaction references a Cell Dependency that does not exist on the current devnet.

After redeployment, make sure the application is using the newly generated deployment information.

---

# 27. Vault Timelock

The current test configuration uses:

```text
timelock = 100
```

The value is encoded as:

```text
0x6400000000000000
```

because:

```text
100 decimal
=
0x64 hexadecimal
```

and the value is represented in the format expected by the contract.

The basic idea is:

```text
Create Vault
     ↓
Lock 5,000 CKB
     ↓
Timelock = 100
     ↓
Attempt to spend
     ↓
Contract checks timelock
     ↓
Transaction succeeds only when conditions are satisfied
```

# 28. Inspect the Vault Transaction

After creating the Vault, save the transaction hash printed by the script.

You can inspect the transaction using:

```bash
ckb-cli rpc get_transaction \
  --hash <TX_HASH>
```

For example:

```bash
ckb-cli rpc get_transaction \
  --hash 0xYOUR_TRANSACTION_HASH
```

You can also inspect individual cells:

```bash
ckb-cli rpc get_live_cell \
  --tx-hash <TX_HASH> \
  --index <INDEX> \
  --with-data
```

For example:

```bash
ckb-cli rpc get_live_cell \
  --tx-hash 0xYOUR_TRANSACTION_HASH \
  --index 0 \
  --with-data
```

Remember that `--index` expects a decimal value with the version of CKB CLI used in this project.

---

# 29. Check the Vault Cell

When inspecting the Vault Cell, pay attention to:

```text
capacity
lock
type
data
```

The `data` field should contain the timelock information used by the Vault contract.

The lock script identifies the `vault-lock` contract.

Conceptually:

```text
Vault Cell
│
├── Capacity
│     └── 5,000+ CKB
│
├── Lock Script
│     └── vault-lock
│
├── Type Script
│     └── none (if applicable)
│
└── Data
      └── timelock = 100
```

# 32. Troubleshooting

## `pnpm exec tsc` reports TS5011

If you see:

```text
TS5011:
The common source directory ... must be explicitly set
```

check that `tsconfig.json` contains:

```json
"rootDir": "."
```

Then run:

```bash
pnpm exec tsc
```

---

## `process` Cannot Be Found

If TypeScript reports:

```text
Cannot find name 'process'
```

install Node.js type definitions:

```bash
pnpm add -D @types/node
```

and ensure the TypeScript configuration includes:

```json
"types": ["node"]
```

Then run:

```bash
pnpm exec tsc
```

---

## `tsx` Command Not Found

If:

```bash
pnpm exec tsx
```

returns:

```text
Command "tsx" not found
```

the project does not currently have `tsx` installed.

This project can instead compile the TypeScript files with:

```bash
pnpm exec tsc
```

and execute the generated JavaScript:

```bash
node dist-ts/contracts/vault-lock/scripts/create_vault.js
```

---

## `fetch failed`

If the script reports:

```text
TypeError: fetch failed
```

check whether the CKB devnet is running.

Start:

```bash
offckb node
```

Then verify:

```bash
ckb-cli rpc get_tip_block_number
```

  offckb node
